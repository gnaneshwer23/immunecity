# Immune engine rules
- Links are identified as `REL-subject-relation-object` (`relId`) and evidence supports a link only via `evidence_records.relationship_id` + `claim_support`; status logic lives in `src/lib/immune/evidenceStatus.ts`; why: concept-level citations must never inflate link coverage.
- One global Scientific Inspector drawer (`src/lib/immune/inspector.ts` store, mounted in Shell) is opened via `inspect()` from any layer; why: one consistent, deep detail view.
- One knowledge graph only: `kg.json` + draft `extensions.ts`. Phase B inventory (`graphInventory.ts`), typed relations (`typedRelations.ts`), provenance (`graphProvenance.ts`), and bounded neighbourhood (`neighbourhood.ts` / `neighbourhood.functions.ts`) read that graph — Neon `ontology_mappings` / `graph_provenance_events` (0017) are additive metadata, never a second KG; ontology external ids must be curator-supplied (empty seed by default).
- Phase C claim helpers (`claimRecords.ts`, `scientificReviewQueue.ts`) keep curation ≠ evidence_status ≠ quality; Gate C requires approved+supports+mapped relationship; unreviewed claims never silently enter the approved graph; conflicts need human review.
