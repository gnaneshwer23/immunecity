# Research rules
- Nature Immunology metadata comes from Crossref via `searchNatureImmunology` (`src/lib/research/natureImmunology.functions.ts`) with parsing in browser-safe `src/lib/research/crossref.ts`; why: no credentials or scraping, and parsing/de-duplication are unit-tested. Library proposals only seed draft literature projects — never evidence approval.

- Evidence collections (`collections.ts` + `collections.functions.ts`, Neon `evidence_collections`) store named member sets of existing graph concept ids + optional evidence_id refs; every list/create/update/delete is ownership-scoped to the signed-in `user_id` with no casual admin list-all; create serializes via `pg_advisory_xact_lock` + transactional count; evidence refs must exist in `evidence_records` or save is rejected; why: research organisation without KG writes (`kgWrite=false`), no cross-member leakage, and no invented evidence ids.
- Evidence-gap labels live in browser-safe `evidenceGap.ts` and use real graph/status signals only; `searchAttempted` without a numeric hit count stays unknown (never coerced to zero); missing Gate C counts → `insufficient_coverage` (not verified absence); explicit zero approved+unreviewed with no draft/bib → `no_mapped_evidence`; copy must state ISI curated coverage / search date-scope — never “no literature exists worldwide”; why: never invent Gate C density or overclaim literature absence.
- Persistence honesty: Neon evidence collections sync across devices for the signed-in member; Workbench drafts use browser localStorage only; why: users must not confuse device-local paths with account sync.
- Research briefs (`researchBrief.ts`) are AI/draft · unreviewed, cite retrieved ids only, fail closed on unsupported ids, and export JSON/Markdown without approving into the KG; why: reproducible, reviewable, source-traceable outputs.
- Phase E scientific brief packages (`scientificBrief.ts`) attach provenance (`exportProvenance.ts`) + curation handoff; unreviewed stays unapproved; collections/paths sync helpers (`planMelanomaInvestigationCollection`, `melanomaInvestigationResearchPath`) never write the KG or auto-approve.
- Claim candidates use explicit review kinds (`literature_candidate` | `extracted_claim` | `reviewed_claim` in `claimRecords.ts`); melanoma pilot source-backed rows are `literature_candidate` only. `isSourceBackedCandidate` means handoff-eligible locator/assertion — **not** claim-verified and never auto-promotes to `reviewed_claim`. `wired: true` means an authenticated `importManifest` submission path exists, not that claims are verified.
