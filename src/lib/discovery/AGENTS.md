# Discovery Intelligence rules
- Research Discovery Radar reuses one KG (`kg.json` + draft `extensions.ts`) — never a second graph and never mass node expansion for Discovery.
- Gap detection is deterministic from real ISI signals (melanoma matrix, evidenceGap, conflicts, trial linkage). LLM drafts explanations only; never invent PMIDs, papers, metrics, or auto-promote to `reviewed_gap`.
- **Gap class** (`gapClass.ts`) is orthogonal to review status: `isi_curation_gap` → `/sme` or `/curation`; `scientific_evidence_gap` only within documented search scope; `research_opportunity` only after evidence assessment (rationale/novelty/feasibility) and human review before `reviewed_opportunity`. Never auto-overwrite reviewed class/opportunity. Insufficient coverage blocks confident scientific-gap claims.
- **Scientific appraisal** (`appraise.ts`) is per research question: support / contradict / background / insufficient_context. Identifier validation (`identifierValidated`) ≠ scientific appraisal (`scientificallyAppraised`). Same PMID on multiple gaps must be re-appraised per question — shared retrieval hit ≠ multi-support. Engineering screen only; SME confirms.
- Deep opportunities (`opportunities.ts`) max 5; promote only when appraisal warrants; never invent PMIDs or force-fill slots. Persist retrieval + appraisal via `persistRetrieval.ts` to Neon (`research_gap_evidence_links`); never mass-approve Gate C / `evidence_records`.
- Retrieval (`retrieve.ts` / `pipeline.ts`) is bounded pilots only; live PubMed / Europe PMC / CT.gov need env flags; failed queries ≠ zero evidence; persist real identifiers only.
- Missing ISI evidence ≠ worldwide literature absence. Prefer status `coverage_insufficient` when Gate C / search signals are incomplete; never coerce unknown hit counts to zero.
- `research_profiles` are ownership-scoped like evidence collections — no casual admin list-all; no required sensitive PII.
- Entitlements `free` | `researcher_pro` | `team` | `enterprise` are server-checked stubs on `research_profiles` — orthogonal to `user_roles`. Quotas (followed gaps, monitor runs, export) enforce in server functions. Team shared profiles / collab are scaffolding only (`team.ts`). No Stripe / payment activation.
- Gap reviews require scientific reviewer/admin power (same gate as evidence curation). Human review is mandatory before `reviewed_gap`.
- Phase 5 ranking is deterministic weighted factors (topic, mechanism, uncertainty, coverage, feedback, recency). Scores are navigation aids — never novelty or scientific importance claims. Feedback lives in `research_gap_feedback`.
- Phase 6 monitor adapters fail closed without live env flags; in-app alerts first (`/discovery/alerts`); email deferred. Monitor never implies automatic scientific review.
- **Evidence Intel 4.0** (`scout.ts`, `claimVerifier.ts`, `crossExamine.ts`, `verifiedGaps.ts`, `reviewRouting.ts`, `intel4.ts`): enhance Discovery 3.0 — do not rebuild Radar/KG/Ask/SME/Neon evidence tables/working retrieval. Title-only ≠ support; keyword hit ≠ support; abstain when insufficient; high model confidence never overrides missing evidence or SME. A/B/C/D cross-exam never consensus-as-truth. No auto Gate C / `reviewed_opportunity`; no silent KG writes; TI flag-off. Accuracy vs gold is null without SME labels.
